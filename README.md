# UI 컬러 로직 스튜디오

이미지의 대표색을 추출하고 UI에 바로 사용할 수 있는 역할별 색상으로 보정하는 브라우저 기반 도구입니다. 상품 카드, 콘텐츠 카드, 배너 미리보기에서 결과를 확인하고 CSS 또는 JSON으로 내보낼 수 있습니다.

- 실행 중 AI 모델·외부 API·API 키가 필요하지 않습니다.
- 업로드한 이미지는 서버로 전송하지 않고 브라우저 안에서 처리합니다.
- 과일, 야채, 한식, 양식, 중식 테스트 이미지 50장을 포함합니다.
- 사용 매뉴얼: 앱 상단의 **사용방법** 버튼 또는 [`public/manual.html`](public/manual.html)
- 9:16 소개 카드: 앱 상단의 **소개 카드** 버튼 또는 [`public/promo.html`](public/promo.html)
- 현재 배포본: [UI 컬러 로직 스튜디오](https://ui-color-logic-studio.study2100-ai.chatgpt.site)

## 주요 기능

- 여러 이미지 업로드 및 일괄 색상 분석
- Oklab 색 공간 기반 대표색 후보 추출
- 균형형, 소프트, 볼드, 다크 보정 프로필
- 채도, 색온도, 표면 틴트, 최소 대비 직접 조절
- 무채색에 가까운 픽셀의 영향 축소 옵션
- 배경마다 검정 또는 흰색 텍스트 자동 선택
- WCAG 대비율 표시 및 최소 대비 기준 반영
- 상품, 콘텐츠, 배너 형태의 실시간 미리보기
- 이미지와 정보 영역을 연결하는 짧고 자연스러운 15% 그라데이션
- 제목, 본문, 메타 정보, CTA 문구 직접 입력
- 개별 역할색 수동 수정 및 자동값 복원
- CSS 변수 복사, 전체 분석 결과 JSON 다운로드
- 결과를 승인 또는 보정 필요로 표시하여 반복 테스트
- Google Play 등록 이미지·쇼츠용 1080×1920 소개 카드 6종 PNG 저장
- IndexedDB에 업로드 이미지와 분석 결과 자동 저장
- PC 재부팅·브라우저 재실행 후 마지막 프로젝트 복원
- 프로젝트 이름별 생성·전환·현재 삭제·전체 초기화
- 이미지를 포함한 프로젝트 JSON 내보내기·불러오기
- 무채색 제외 설정별 테스트 이미지 50장 분석 캐시

## 로컬 실행

### 준비 사항

- Windows 11, macOS 또는 Linux
- Node.js `22.13.0` 이상
- 최초 패키지 설치를 위한 인터넷 연결

```bash
git clone <REPOSITORY_URL>
cd ui-color-logic-studio
npm install
npm run dev
```

터미널에 표시되는 `http://localhost:5173`을 브라우저에서 엽니다. Windows PowerShell과 명령 프롬프트에서도 같은 명령을 사용할 수 있습니다. 저장된 프로젝트가 다른 브라우저 주소로 분리되지 않도록 개발 포트는 5173으로 고정되어 있습니다.

프로덕션 형태로 확인하려면 다음 명령을 사용합니다.

```bash
npm run build:local
npm run start
```

### npm 스크립트

| 명령 | 용도 |
| --- | --- |
| `npm run dev` | 로컬 개발 서버 실행 |
| `npm run build:local` | Windows, macOS, Linux용 로컬 빌드 |
| `npm run start` | 빌드된 앱 실행 |
| `npm run lint` | ESLint 검사. 저장소의 배포 환경용 Bash 보조 스크립트를 사용하므로 Windows에서는 WSL 또는 Git Bash 권장 |
| `npm run build` | 호스팅 환경용 검증 빌드. Bash와 GNU 도구 필요 |
| `npm test` | 호스팅 환경용 빌드 후 렌더링 테스트 실행 |

일반 사용자는 `npm install`, `npm run dev`만으로 충분합니다. 색 추출을 위해 별도 서버, 데이터베이스, Python, AI 프로그램을 실행할 필요가 없습니다.

## 사용 순서

1. 이미지 업로드 영역에서 한 장 이상을 선택하거나 **테스트 50장 불러오기**를 누릅니다.
2. 보정 프로필과 채도, 색온도, 표면 틴트, 최소 대비를 조절합니다.
3. 대표색 후보와 RAW KEY → CORRECTED 결과를 확인합니다.
4. 상품, 콘텐츠, 배너 탭을 바꾸며 실제 UI 조합을 검토합니다.
5. 필요한 경우 제목·설명·메타·버튼 문구와 각 역할색을 직접 수정합니다.
6. **CSS 복사** 또는 **프로젝트 JSON**으로 결과를 가져갑니다.

작업 중인 이미지, 팔레트 수정값, 문구와 검수 상태는 IndexedDB에 자동 저장됩니다. 같은 브라우저와 주소로 다시 접속하면 마지막 프로젝트가 자동 복원됩니다.

## 프로젝트 저장과 복원

- 상단 프로젝트 선택 메뉴에서 저장된 작업을 전환할 수 있습니다.
- 프로젝트 이름 입력란을 수정하면 새 이름으로 자동 저장됩니다.
- **새 프로젝트**는 빈 작업 공간을 만듭니다.
- **현재 삭제**는 선택한 프로젝트만 삭제합니다.
- **전체 초기화**는 모든 프로젝트와 테스트 이미지 분석 캐시를 삭제합니다.
- **프로젝트 JSON**은 업로드 이미지 데이터까지 포함한 백업 파일을 만듭니다.
- **JSON 불러오기**는 이 프로그램에서 내보낸 프로젝트를 새 프로젝트로 복원합니다.

브라우저 저장소는 현재 브라우저 프로필과 접속 주소에 귀속됩니다. 시크릿 모드 사용, 브라우저 데이터 삭제 또는 다른 PC로 이동하기 전에는 프로젝트 JSON을 별도로 보관하세요.

더 자세한 설명은 앱의 `/manual.html`에서 확인할 수 있습니다.

## 컬러 처리 흐름

1. 이미지를 Canvas로 읽고 분석용 크기로 축소합니다.
2. 픽셀을 sRGB에서 Oklab으로 변환합니다.
3. 중심부 가중치, 채도, 명암 극단값, 무채색 옵션을 반영해 후보 픽셀의 점수를 계산합니다.
4. 후보를 여러 색상 군집으로 묶고 점유율과 색차를 기준으로 대표색을 고릅니다.
5. 선택한 프로필과 보정값을 HSL 기반으로 적용합니다.
6. 대표색에서 UI 역할별 팔레트를 파생합니다.
7. 각 배경에 대해 어두운 텍스트와 흰 텍스트의 대비율을 비교하여 더 안전한 쪽을 자동 선택합니다.

텍스트 색은 무조건 검정이 아닙니다. 대표색과 그라데이션 배경이 어두우면 흰색을, 밝으면 어두운 색을 선택하며 보조 텍스트도 목표 대비를 만족하도록 보정합니다.

## 생성되는 UI 역할색

| 역할 | CSS 변수 | 용도 |
| --- | --- | --- |
| Key | `--ui-key` | 대표 강조색 |
| On Key | `--ui-key-foreground` | 대표 강조색 위 텍스트 |
| Surface | `--ui-surface` | 카드 및 정보 영역 바탕 |
| Gradient A | `--ui-gradient-top` | 이미지와 연결되는 시작색 |
| Gradient B | `--ui-gradient-bottom` | 그라데이션 끝 및 본문 배경 |
| Text | `--ui-text-primary` | 주요 텍스트 |
| Muted | `--ui-text-secondary` | 설명과 메타 정보 |
| Accent | `--ui-accent` | 버튼과 상태 강조 |
| On Accent | `--ui-accent-foreground` | 버튼 위 텍스트 |
| Border | `--ui-border` | 경계선과 구분 요소 |

CSS 복사 결과 예시:

```css
:root {
  --ui-key: #B96832;
  --ui-key-foreground: #151514;
  --ui-surface: #F4E5DB;
  --ui-gradient-top: #D8A987;
  --ui-gradient-bottom: #EAC7AE;
  --ui-text-primary: #151514;
  --ui-text-secondary: #5D5149;
  --ui-accent: #8F7330;
  --ui-accent-foreground: #FFFFFF;
  --ui-border: #D0BDB0;
}
```

위 값은 예시이며 실제 결과는 이미지와 보정 설정에 따라 달라집니다.

## 그라데이션 연결 방식

미리보기는 이미지 영역과 정보 영역 사이에 별도 선을 사용하지 않습니다. 이미지 끝부분 위에 투명색에서 팔레트 배경색으로 이어지는 짧은 오버레이를 겹쳐 경계를 흐립니다.

- 상품·콘텐츠: 이미지 하단 약 15% 범위에서 세로 방향으로 연결
- 배너: 데스크톱에서는 이미지/텍스트 경계 약 15%를 가로 방향으로 연결
- 모바일 배너: 이미지 하단 약 15%를 세로 방향으로 연결

그라데이션이 너무 넓다면 `app/globals.css`에서 `.photo-bridge`의 `height: 15%`를 조절합니다. `linear-gradient()` 안의 중간 퍼센트는 요소 높이가 아니라 색상 전환 위치입니다.

## 테스트 이미지 50장

| 분류 | 수량 | 예시 |
| --- | ---: | --- |
| 과일 | 10 | 사과, 바나나, 오렌지, 키위, 포도 |
| 야채 | 10 | 토마토, 당근, 브로콜리, 파프리카, 가지 |
| 한식 | 10 | 비빔밥, 김치찌개, 불고기, 떡볶이, 김밥 |
| 양식 | 10 | 피자, 파스타, 스테이크, 크루아상, 연어 |
| 중식 | 10 | 베이징덕, 마파두부, 딤섬, 볶음밥, 훠궈 |

파일은 `public/test-images/`에 WebP 형식으로 포함되어 있습니다. 각 이미지의 원본 Wikimedia Commons 페이지는 [`public/test-images/manifest.json`](public/test-images/manifest.json)에 기록되어 있으며, 앱의 테스트 결과 카드에서도 열 수 있습니다.

이미지를 재배포하거나 상업적으로 사용할 때는 각 원본 페이지의 저작자 표시와 라이선스 조건을 개별적으로 확인하세요.

## JSON 출력

**프로젝트 JSON**은 업로드 이미지 데이터, 이미지 이름과 크기, 대표색, 후보색, 역할별 팔레트, 대비율, 검토 상태, 입력 문구와 보정 설정을 포함합니다. 다른 PC로 옮기거나 브라우저 데이터 삭제 전에 백업하고, 프로그램의 **JSON 불러오기**로 다시 복원할 수 있습니다.

## GitHub에 등록할 때

이 폴더를 새 GitHub 저장소에 올리려면 저장소를 만든 뒤 원격 주소를 연결합니다. 기존 원격을 보존하려면 `origin` 대신 `github`라는 이름을 사용할 수 있습니다.

```bash
git remote add github https://github.com/<ACCOUNT>/<REPOSITORY>.git
git push -u github main
```

비공개 업무 코드나 이미지가 포함되어 있다면 GitHub 저장소를 **Private**로 생성하고, 테스트 이미지의 재배포 조건을 먼저 확인하세요.

현재 저장소에는 프로젝트 코드에 대한 `LICENSE` 파일이 포함되어 있지 않습니다. 따라서 공개 저장소에 올린다고 해서 자동으로 자유 이용이 허용되지는 않습니다. 배포 정책에 맞는 코드 라이선스를 정한 뒤 별도 `LICENSE` 파일을 추가하세요. 테스트 이미지는 코드와 별개이며 각 Wikimedia Commons 원본 페이지의 라이선스를 따릅니다.
